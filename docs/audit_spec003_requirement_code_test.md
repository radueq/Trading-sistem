much weight each finding deserves:
- A structural/mechanism check (a field exists and is populated, a
  generic code path exists) IS reliably confirmable by reading the
  code -- those get "MET (by inspection)."
- A **numeric formula's arithmetic correctness**, or **wiring across an
  entire untested mode/path**, is NOT reliably confirmable by reading
  the code alone -- those stay **TEST-COVERAGE GAP** without the "MET
  (by inspection)" upgrade, since inspection cannot rule out a subtle
  error the way it can rule out a missing mechanism.
- Findings where the code's behavior is directly, concretely confirmed
  (not inferred) and plausibly contradicts the spec's own explicit text
  are tagged **DEMONSTRATED DEFECT**; findings where the behavior is
  confirmed but whether it actually violates the contract is a reading
  Radu still needs to make are tagged **SUSPECTED ISSUE -- VERIFICATION
  PENDING** instead.
